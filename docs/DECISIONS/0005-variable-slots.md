# 0005: スロットの数を変えられるようにする

- 状態: 採用（2026-11-05、STEP 7 の後）
- 関連: 企画書 §5・§17、STATE の Q-11、design/03 §2.1、design/04 §1・§2・§4、LEARNINGS L-21

## Context

企画書 §17 は「キーワード 2 個 + ゲームジャンル 1 個を基本とする」と決めていた。STEP 7 まではこの 3 つを固定のスロット（`keyword1`・`keyword2`・`genre`）として作った。

STEP 7 の後にメンテナーが触って、「ジャンルを一番左において、キーワードもジャンルも可変式にできるとさらに面白いかも」と要望した。キーワードを 1 つに絞れば発想の起点がはっきりし、増やせば組み合わせが意外になる。ジャンルを外せば AI がジャンルから選び、2 つ重ねればジャンルの掛け合わせになる。

## Decision

- スロットを種類（ジャンル・キーワード）つきの並びにする。ジャンルは 0〜3（初期 1）、キーワードは 1〜5（初期 2）。ジャンルを左、キーワードを右に並べる。
- 企画書の「キーワード 2 個 + ジャンル 1 個」は初期の数として残す。
- ジャンルが 0 のときは「ジャンル自由」とし、AI にはキーワードに合うジャンルを選ばせる。2 つ以上なら掛け合わせる。
- 組み合わせの型を `{ genres: string[]; keywords: string[] }` にする。IPC の入力は古い形（`keyword1`・`keyword2`・`genre`）も読む。
- 保存の形を変える。
  - DB は版 2。`ideas` に `keywords`・`genres`（JSON 配列）の列を足し、版 1 の列から埋める。古い列は消さずに先頭の語を入れて残す（DECISIONS/0004 の「追加だけ」に従う）。
  - 既存の DB の版を上げる直前に、ファイルの写し（`<DB>.before-v2`）を 1 回だけ取る。マイグレーションはトランザクションで行うが、初めて実データの形を変えるので念のため。
  - 作業状態は版 2。版 1 の 3 スロットを `g1`・`k1`・`k2` に直し、固定・カテゴリ・直近の語を引き継ぐ。
- キー操作は 1〜9 で左から数えたスロットを引き直す（Shift で固定）。

## Alternatives

- 3 スロットのまま、ジャンルだけ「なし」を選べるようにする: 要望の「可変式」に届かない。
- 上限を設けない: 画面が折り返しすぎ、AI への指示も散る。触って足りなければ上限を上げる。
- DB の古い列を消して作り直す: 表の作り直しになり、壊れたときの救出（L-20）も複雑になる。列を足すだけにした。

## Consequences

- 抽選・指示文・保存・一覧・出力・派生のすべてが配列を扱う。Markdown の見出しは「ジャンル」「キーワード」の 2 行になり、ジャンルが先に来る。
- ジャンルでの絞り込みは、どれか 1 つのジャンルが一致すれば出す（`json_each`）。
- 生成の質の評価（`npm run eval:ideas`）の組み合わせは 2 + 1 のまま。ジャンル 0 や 2 つ以上での質は、まだ評価していない。
